# public/data/jobfile (WP-03, M0-11)

`base_design_es_2026_04.json` is generated by `tools/content/extract_jobfile.py` from the real
`BASE_DESIGN_ES_FD0AEBB95776A72.job` and `_job.digest` (reference-design release v2026.04). Facts only:
the bitstream (`pgm.map`, 76.9 MB inflated) is never inflated or copied, nor are the boundary-scan bit
patterns or the build machine's paths. `JOB_FORMAT.md` specifies the container for WP-36's in-browser parser.

Core-v1 fields (`JobFileFacts`): `name` (design name), `file`, `date`, `zipVersion`, `manifest[{name, bytes}]`,
`header{inDie, extDie, package, idcode, idmask, silsig, chksum, designVersion, bsrLength, action,
program{fabric, snvm, envm}, verify{...}, bitstreamDigest}`, `programmers[{name, tckHz, sckHz?, maxTckHz,
irLength}]`, `digests{fabric, envm, snvm, bitstream}`, `productionIdcode`, `source`.

Extra fields: `file_facts` (size, SHA-256 of the .job and of _job.digest), `text_header`, `manifest_block`,
`zip.entries` (method, sizes, CRC, offsets), `header_xml` (every scalar field), `bsr_io_states` (600 boundary
-scan cells: `[bsr_index, ball, port, macro_cell, input, output, outputEnable]`, 189 named), `project` (the
FlashPro .pro XML: TCK per programmer, Vdd 2500 for the original FlashPro), `job_export`, `programmer_settings`,
`digest_file`, `idcodes`, `checks` (cross-checks that the extractor asserts), `not_published`.

ES die idcode `0f81a1cf` (this job); production die `1f81a1cf` (FlashPro log of a production MPFS250T).
