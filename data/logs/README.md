### LogLine (core-v1 fields first)

| Field | Type | Meaning |
|---|---|---|
| `text` | string | the captured line, verbatim (U-Boot/Linux: the 3-space rst indent removed, tabs kept) |
| `t` | number? | seconds. HSS prints `[%lu.%05lu]` (modules/debug/hss_debug.c L25-26): microseconds padded to only 5 digits, so `[6.18393]` is **6.018393** s; `t` is the decoded value, which makes the HSS timestamps monotonic. Linux: printk seconds since kernel start |
| `event` | string | the hardware/firmware event that prints the line: `ddr.segconfig`, `mmc.select.sd.fail`, `mmc.select.emmc.pass`, `boot.copy`, `hart.u54_1.Init->SetupPMP`, `hss.ipi_poll_service.Init->Monitoring`, `eth0.link.up`, ... Continuation lines carry the event of the message they belong to |
| `args` | {string: string\|number}? | values on the line (`boot.copy`: `bytes` 748336, `dest` "0xa0000000"); lists are space-joined |
| `elided` | true? | marker for trimmed systemd lines (`text` is "") |
| `reconstructed` | true? | text not captured (FlashPro PROGRAM/VERIFY bodies only) |
| `kind` | "line" \| "elided" | |
| `id` | string | stable id, `<file>.<source line>` (`hss.053`) |
| `src_line` | int | line number in the source (see `source.src_line_base`) |
| `t_raw` | string? | timestamp digits as printed |
| `hw` | bool | false for lines with no hardware cause (kernel bookkeeping) |
| `msg` | string? | HSS: lines printed by one call share a message id (`hss.m007`) |
| `flags` | string[]? | `cont` (continuation), `truncated` (cut at the poster's right margin; `truncation_note` gives the format string), `ts_unpadded`, `tinycli_line_header` (line starts with the TinyCLI `>> ` prompt), `device_specific`, `interleaved` (two writers on one console line) |
| `path` | string? | HSS: `common` or `error.pmp_timeout` (lines 72-100 are the poster's failure) |
| ElidedMarker | `{kind:"elided", elided:true, text:"", id, src_lines:[a,b], count, reason}` | |

`hss.json` also has `continuation`: the remaining boot-service transitions (SetupPMPComplete -> ZeroInit
-> Download -> OpenSBIInit -> Wait -> Complete) with the line format; no capture of them exists, so the
simulator must mark lines built from it as reconstructed.

`flashpro_device_info.json`: `lines` = the real DEVICE_INFO log, each with `text_source` (verbatim, blog
author's notes removed), `template` (job-file values replaced by `{placeholders}`), `text` (template
rendered with `defaults`: ES idcode 0f81a1cf, MPFS250T_ES, checksum 24e4, design version 0x65b8, FlashPro6,
4 MHz), `substitutions`, `phase`, flags `annotation_removed` and `es_value_unknown` (device-read values such
as digests and DSN that the job file cannot supply). `program.lines` / `verify.lines` are reconstructed.

`hss_modern_banner.json`: `format` (template joined with LF), `placeholders` ({name: C format}),
`placeholder_details`, `versions_at_commit`, `def_config`, `differences_from_hss_json`, `real_sample_2022`.

`tinycli.json`: `commands` [{name, help, args?, table, src_line, enabled_in_def_config}] for every
command the Icicle `def_config` enables (sub-commands as `DEBUG SEG`), `tables` (all five C tables with
`#if` guards), `preboot`, `line_header`.
